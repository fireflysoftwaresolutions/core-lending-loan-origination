# Managed Loan evidence association

`POST /api/v1/managed-application-evidence/applications/{applicationId}/actions/{actionId}` attaches the exact immutable Document reference and metadata to a real managed Loan application. The path, body, signed party, configured Loan and Document namespaces, original action, and full intent must agree. New association returns 201; exact original-action replay returns 200; changed intent returns 409. Typed 503 outcomes preserve `REFUSED`, `OUTCOME_UNKNOWN`, and `COMMITTED_RESPONSE_UNAVAILABLE` separately. Recover only the original action and exact reference, never mint another action after an uncertain write.

The owner locks and verifies the real managed application, primary `PRIMARY_APPLICANT`, active document classification, and DRAFT/PENDING_DOCUMENTS catalogue identities. It inserts mapped `application_document` and immutable `loan_evidence.association` rows in the same bounded Spring Data transaction as the canonical event/outbox. Mandatory remains NULL and verification PENDING; no income, employment, approval, or verification result is invented. Exact replay verifies the full retained graph and completed canonical pair. Both mutation and replay require current authority; generic response caching is disabled.

`GET` on the same path independently revalidates the signed party, original action, owner binding and current read policy. It returns 200 only after verifying the retained association, metadata and completed pair. A 204 proves the current managed application and primary borrower but finds no association for that original action; it is not an upload or a successful attachment. Read responses use no-store and do not append business or audit events. Typed `OBSERVATION_UNAVAILABLE` is distinct from a write outcome.

Loan stores references and verified metadata only. The Document owner remains responsible for custody and actual bytes; Domain must independently hash the actual scoped Document content before invoking this operation. The owner fixture uses controlled external Document reference values and does not prove that cross-owner step. Failed association never authorizes deletion of retained Document custody.
